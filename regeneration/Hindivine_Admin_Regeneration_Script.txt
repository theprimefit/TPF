B1. ARCHITECTURE
----------------
* One JSON document holds all data ("state"). It is kept in localStorage under
  the key  hindivine.admin.v1  and mirrored to a Google Sheet (see B9).
* core.js exports window.ADMIN (and module.exports in Node):
    createAdmin(storage, clock?)  → the admin API (all functions in B3–B8)
    memoryStorage(), defaultState(), splitIncentive(), matchItem(),
    rangeFor(name, today), monthRange('YYYY-MM'), isoDate(date), daysBetween()
    constants: KINDS, SALE_TYPES, EXPENSE_CATEGORIES, SHEETS, KEY, ROLES,
    APPT_MODES, APPT_STATUS, PAY_METHODS, DEFAULT_PERMS, LEAD_PRIORITIES,
    DEFAULT_LISTS
* Every mutating function: validates (throws Error with a plain message),
  changes state, calls log(action, detail), then save(). save() writes
  localStorage and calls every onChange(listener) with source 'local'
  (or 'remote' when data was loaded from the sheet).
* app.js renders screens as HTML strings into <main id="view">, uses event
  delegation (data-go="screen", data-act="action", data-filter="…"),
  one modal <dialog> for all forms, and toast() for messages.
* export.js exports window.EXPORT = { pdf, xlsx, jpeg, pdfText }.

B3. STOCK RULES
---------------
* stockOf(item) = item.opening + sum of its moves.
* Purchase line → move +qty (type purchase). Sale → move −qty (type sale).
* Injection kit: for every injection sale, for each kit entry add a move
  −(kit.qty × pens) of type 'kit'. Defaults per pen: Travel Bags 1,
  Ice Gel Packs 1, Alcohol Swabs 16, Needles 2. Editable (setKit) and can be
  switched off (settings.kitOn). Deleting or editing a sale removes its moves.
* A sale is refused if the product stock is lower than the quantity; kit items
  may go negative (never block a sale).
* Low stock: stock ≤ lowAt, unless settings.stockAlerts is false or the item
  has alertOff.
* Order required: item.orderAt != null and stock < orderAt.
* stockReport(range): per item opening (at range start), purchased, sold,
  used (kit), adjusted, current.

B4. SALES & INCENTIVES
----------------------
* Sale types: injection (per pen), protein (once per sale), diet support
  (plan: 1 Month ₹1000 / 3 Month ₹2000 incentive).
* References: refId (100%) plus optional sharedId with sharePct
  (blank = 50 → 50-50; any custom %).
* Rate for a person: member's own rate (incInjection / incProtein) if set,
  else the product's incentive override, else the clinic default
  (₹1000 injection, ₹500 protein). Diet uses the plan incentive.
* If all references have the same rate: split total exactly with remainder to
  the first (splitIncentive). Otherwise each gets round(rate × units × pct/100).
* Incentive status Off → that person's share is ₹0.
* patientType auto: 'renewal' if the patient bought before, else 'new'.
* Revenue = sales amounts + paid OPD fees (not cancelled).

B5. SALARY
----------
salarySheet('YYYY-MM') per member: mode = payMode.
  salary counted unless mode 'incentive' (and member joined by month end);
  incentive counted unless mode 'salary'; total = salary + incentive.
postSalary(month) books Salary and Incentive expenses (replacing an earlier
booking of the same month).

B6. OPD APPOINTMENTS
--------------------
saveAppointment: date, time, patient (find or create by mobile/name), mode
clinic|online, optional service (added to the services list), fee (default
settings.consultFee), link for online, paid + payMethod, status, notes, by,
leadId. updateAppointment(patch) for status / paid. appointmentStats(range):
total, booked, completed, cancelled, noshow, clinic, online, fees (paid, not
cancelled), unpaid.

B7. LEADS (CRM)
---------------
saveLead requires name and mobile; refuse a second lead with the same mobile.
New lead: status New, history 'created'. addLeadActivity(id, {type, text,
followUp, followTime}) adds history; a call/WhatsApp on a New lead moves it to
Contacted. setLeadStatus records 'from → to'. convertLead(id, appointment?)
creates/finds the patient; with an appointment books it (service = lead
interest), status 'Appointment booked'; without, status 'Converted'.
leadStats(range, filter): total, open, won, conversion %, dueToday, overdue,
hot, newToday. Closed = Converted, Not interested, Lost.
Front Desk sees leads assigned to them, unassigned ones and ones they created.

B8. LOGINS, ROLES, ACTIVITY LOG
-------------------------------
* PIN 4–6 digits; stored as SHA-256(salt + ':' + pin) hex with a random salt
  and the PIN length (len) so the keypad checks as soon as enough digits are
  typed. Staff PINs are also stored in plain text (field pin) so the Super
  Admin can view/reset them; the Super Admin PIN is never stored in plain text.
* At least one Super Admin must always exist (cannot delete/demote the last).
* Roles: Super Admin = everything. Admin / Manager / Front Desk = screens in
  settings.perms (editable matrix in Settings) + "can delete" flag.
  Default Admin: all except Settings, can delete. Default Manager: dashboard,
  today, appointments, leads, sell, sales, patients, renewals, products,
  inventory, purchases, expenses, reports, activity. Default Front Desk:
  appointments, leads.
* setActor(name) after sign-in; every log() entry stores who did it.
* Logout after 15 minutes idle.

B9. GOOGLE SHEET DATA STORE (Code.gs)
-------------------------------------
Sheet ID: 1_aKPoHJaJfQ6awuoG7ihufQzOBhw8I84yipErlWO1_Y

* doGet?action=load&secret= → {ok, updated, by, state}.
* doPost {action:'save', secret, state, sheets, base, by, force} → refuses
  with {conflict:true} when another device saved after `base`; otherwise
  writes the JSON state in 40,000-character chunks to _AppData (A1 holds
  {updated, chunks, by}) and rewrites the readable tabs.

  Expenses, Renewals, Activity Log (rows built by core.sheetsData()).
* App side: load on sign-in, every 30 s, on returning to the app, on
  pull-down and the refresh button; save 1.5 s after each change; silent
  (only the refresh icon spins); offline changes retried every 60 s; if both
  sides changed, ask "Keep this device's data" or "Use Google Sheet data".
  "Unsaved" = hash of exportState() differs from the last saved/loaded hash.
  exportState() removes device-only settings.

B11. EXPORTS (export.js)
